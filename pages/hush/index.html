BIP-352 silent payments desk for PRL · one static address, a whisper of unlinkable outputs

Honest limits — read before you hush

  • Forward-looking standards desk, not a wallet: BIP-352 is not yet supported by Pearl wallet software (Oyster). This page implements the published BIP-352 math byte-exact — pinned against the official test vectors — so the ecosystem has a correct reference when support lands.
  • Derived prl1… outputs are valid Pearl Taproot addresses for manual sweeping: each is a well-formed bech32m v1 32-byte address. This page never signs and never broadcasts — moving funds is on you, with a real wallet.
  • Silent-payment addresses use sp1…/tsp1… exactly as published in BIP-352. No Pearl-specific HRP was invented.
  • Keys live in this page's memory only and the Send tab wipes pasted input secrets after deriving. Anyone watching your screen or with access to this browser session sees them. Wipe when done.
  • Quiet about skips: per the BIP-352 reference, inputs that can't contribute to the shared secret are skipped, not failed — the Send tab still refuses non-taproot inputs loudly, because this desk only speaks taproot.

NIGHT · 02 Send — derive unlinkable outputs

Describe the inputs you will spend from and the silent-payment address(es) you are paying. The desk runs the BIP-352 sender math and hands you the exact taproot outputs to include in your transaction. This desk only derives from taproot key-path inputs — anything else is refused loudly.
